## What this project is

A local web app (`localhost:3100`) that runs an autonomous **ExtraHop
RevealX network-detection investigation agent**. A human opens a detection,
the agent (backed by Claude Code via the Claude Agent SDK, or the Pi coding
agent) pulls evidence through a **read-only** broker CLI (`./excli-interface`,
wrapping the ExtraHop REST API), reasons through an evidence ladder
(metrics → records → packets), and produces a disposition + report. Any write
back to ExtraHop goes through a **governed propose/approve/execute path** — the
agent never executes writes itself.

Repo: `github.com/swsloan/eh-investigator-agent` (public). Local path:
[eh-investigator-agent](.) inside `~/git-repo/ExtraHop Investigation Agent/`
(that outer folder also holds unrelated version-drop artifacts, screenshots,
and a pptx — the git repo is only the `eh-investigator-agent/` subfolder).

## Open issues, by thread

### Active work: the eval/ladder quality loop (issue #128)
[#128](https://github.com/swsloan/eh-investigator-agent/issues/128) has two
halves: **(a)** `plaintext-http-creds` disposition wrong in 3/4 runs, and
**(b)** every run over-climbs to packets. PR #155 fixes (b) — root cause was
missing **scope** discipline (the ladder had a stop-rule but nothing telling
it which activity belongs to *this* detection's window), confirmed via new
`climb.json` diagnostic artifacts retained across eval disposal. Validated:
`false_climb` 9/9 → 0/2 on the target case, cost ~$9.48→~$5.3, no
under-investigation regression on 3 guard cases.

**What's still open after #155 lands:** (a), the disposition-accuracy half,
is explicitly deferred — `plaintext-http-creds` stays `scoring.disposition:
false` in the case file until more runs confirm the verdict is now stable.
Don't re-enable it on fewer than a handful of runs. (For fuller background on
three earlier confident-wrong-answer eval bugs and the disposal-deleted-the-
evidence problem PR #155's first commit fixes, see the operator's prior
session notes — not in-repo, but worth asking for if you need the trail.
A Claude Code session on this repo also gets the `eval-harness-gates` memory
file loaded automatically, which carries the same trail.)

  beating that noise floor.

## Useful facts to not re-derive

- Eval cost is authoritative; token counts over-count cache reads — gate and
  compare on cost, not tokens.
- Memory (Graphiti/FalkorDB) writes happen at investigation **close**, not
  continuously.
- `graphiti/config.yaml` is volume-mounted (`:ro`) — edit + `docker compose
  restart graphiti-mcp`, no rebuild needed. Skills are baked into the app
  image — edit + rebuild.
- Eval store: `/app/data/eval` (persisted volume) — `history.jsonl`,
  `<run>.json`, `cassettes/`, `label-overrides.json`.
- Deploy is `./scripts/deploy.sh` from the repo root (self-locating, runs
  `docker compose … up -d --build eh-investigator`); this checkout **is**
  both the git repo and the deploy source, so commit/push and deploy act on
  the same tree.
